## 1. Architectural Philosophy

The ONIONVISION architecture adheres to three core engineering principles:

1. **Separation of Training and Inference:** Model training is isolated in offline ML scripts (`ml/training/`) producing versioned model artifacts (`ml/models/`). The FastAPI application only loads frozen model artifacts for inference and never initiates training cycles inside HTTP request handlers.
2. **Explainability Over Black-Box Claims:** Grading decisions are generated by a deterministic, transparent rules engine combining physical measurements, visual quality confidence, and defect areas with explicit reason codes and source traceability.
3. **Evidence-Based Engineering:** The system strictly consumes actual labels discovered in audited datasets. It never invents defect categories, accuracy numbers, or official agricultural certifications.

## 3. Computer Vision Subsystem Components (`backend/app/cv/`)

### 3.1 `morphometry.py`
Computes scientifically defensible geometric attributes from masks and contours:
- $\text{area\_pixels} = \text{contourArea}(C)$
- $\text{perimeter\_pixels} = \text{arcLength}(C)$
- $\text{major\_axis\_pixels}, \text{minor\_axis\_pixels}$ via fitted ellipse or rotated min-area bounding box
- $\text{aspect\_ratio} = \frac{\text{major\_axis}}{\text{minor\_axis}}$
- $\text{circularity} = \frac{4 \pi \cdot \text{area}}{\text{perimeter}^2}$ (safe against division by zero)
- $\text{equivalent\_diameter\_pixels} = \sqrt{\frac{4 \cdot \text{area}}{\pi}}$

### 3.2 `calibration.py`
Evaluates reference objects and calculates physical conversion factors:
- Identifies `Reference-Object` detections from segmentation.
- When verified physical dimension is provided:
  $$\text{mm\_per\_pixel} = \frac{\text{known\_reference\_diameter\_mm}}{\text{reference\_pixels}}$$
- If physical reference dimension is unconfigured, returns `CALIBRATION_CONSTANT_REQUIRED` and leaves physical size as `null` without guessing.

### 3.3 `extractor.py`
Extracts individual instances from full-scene images:
- Produces rectangular crops and precision masked crops (zeroing out pixels outside the instance mask).
- Enforces quality gate validation: minimum dimension $\ge 15$ px, visible onion pixels $\ge 80$.

### 3.4 `confidence.py`
Assigns deterministic triage review states based on multi-modal evidence:
- **`AUTO_ACCEPTABLE`**: High segmentation confidence ($\ge 0.60$), high quality confidence ($\ge 0.70$), and regular geometry.
- **`REVIEW_RECOMMENDED`**: Moderate confidence, uncalibrated scale, or elongated aspect ratio ($> 1.80$).
- **`MANUAL_REVIEW_REQUIRED`**: Invalid crop/mask, critically low confidence ($< 0.40$), or zero detections.

### 3.5 `watershed.py`
Provides an OpenCV classical watershed segmentation fallback when YOLO weights are missing or fallback is explicitly requested. Output is clearly tagged with `source: "watershed"`.

### 3.6 `pipeline.py`
Coordinates the complete inspection workflow, tracks per-stage execution latencies, and aggregates batch statistics.

## 5. Source Traceability & Explainability

Every inspection attribute is explicitly traceable to its originating subsystem:
- `segmentation_source`: `"yolov8n-seg"` or `"watershed"`
- `quality_source`: `"mobilenetv3-small"`
- `measurement_source`: `"mask_morphometry"`
- `calibration_source`: `"reference-object"`
- `grading_source`: `"deterministic-rule-engine"`

## 6. Security & Data Integrity Controls

- **File Validation**: All uploads are verified with binary integrity checks using Pillow (`img.verify()`) to prevent disguised malicious files.
- **Path Traversal Protection**: Filenames are sanitized via regular expressions and verified to ensure file paths do not escape the designated upload directory.
- **Payload Limits**: Upload sizes are capped by default at 15MB, rejecting excessive payloads with HTTP 413.
- **Environment Isolation**: Configuration keys and file paths are loaded strictly via `pydantic-settings` from environment variables, preventing hardcoded secrets.
